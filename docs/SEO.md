# راهنمای سئو — رستوران وطندار

این سند همراه با اصلاحات سئوی `app/layout.tsx` اضافه شده و مسیر کامل
«بالا آمدن سایت در جست‌وجوی گوگل (مثلاً سرچ «وطندار»)» را توضیح می‌دهد.

---

## ۱) چه چیزهایی درست شد؟

| مورد | قبل | بعد |
|---|---|---|
| `robots.ts` و `sitemap.ts` | در **ریشهٔ پروژه** بودند و Next هرگز آن‌ها را نمی‌ساخت | به `app/` منتقل شدند؛ حالا `/robots.txt` و `/sitemap.xml` واقعاً منتشر می‌شوند |
| favicon | همان `logo1.png` با حجم **۱.۸MB** | `favicon.ico` چندسایزی (۱۵KB) + آیکن‌های ۱۹۲/۵۱۲/ماسک‌بل |
| تصویر اشتراک‌گذاری (OG) | `card-image.jpg` با ابعاد ۶۰۰۰×۴۰۰۰ و حجم ۱.۹MB | `og-image.jpg` استاندارد ۱۲۰۰×۶۳۰ (~۱۴۰KB) با لوگوی برند |
| manifest PWA | `start_url: /admin` (!)، آیکن ۵۱۲ موجود نبود | `start_url: /`، آیکن‌های واقعی، `dir: rtl`، شورت‌کات منو و شعبه‌ها |
| Structured Data | مقادیر placeholder مثل `+98-513-xxx-xxxx` و «آدرس دقیق رستوران» | از دیتابیس ساخته می‌شود: `WebSite` + `Organization` + یک `Restaurant` per شعبهٔ فعال + `Menu` کامل + `aggregateRating` واقعی از جدول `reviews` |
| تگ‌های تکراری در `<head>` | آیکن/manifest/theme-color/verification هم در metadata و هم دستی | فقط Metadata API_next (بدون هیچ تگ دستی تکراری) |
| تگ‌های تأییدیهٔ ساختگی | `yandex-verification-code` و `yahoo-verification-code` | حذف شدند (فقط تأییدیهٔ واقعی گوگل ماند) |
| فونت سایت | `--font-sans` به فونتی اشاره می‌کرد که هرگز لود نمی‌شد → رندر فارسی با فونت پیش‌فرض مرورگر | وزیرمتن به‌صورت self-host با `next/font` (preload + بدون درخواست خارجی) |
| متادیتای هر صفحه | نداشت | `canonical` + title/description اختصاصی برای `/menu`، `/branches`، `/about` و `noindex` برای `/admin`، `/login`، `/my-orders` |
| تصاویر شعبه‌ها | ۷ تا ۲۱ **مگابایت** هر عکس (جمعاً ~۱۴۵MB در ریپو) | بهینه‌سازی به حداکثر ۲۰۰۰px (~۰.۴MB هر عکس) → کل `public/` از ۱۶۰MB به ۱۵MB |
| صفحهٔ اصلی برای خزندهٔ بدون JS | خالی | بلوک `<noscript>` با عنوان، توضیح و لینک‌های داخلی |

## ۲) دامنهٔ اصلی (مهم‌ترین قدم فنی)

تمام آدرس‌های canonical، sitemap و JSON-LD از یک متغیر خوانده می‌شوند:

```
NEXT_PUBLIC_SITE_URL=https://دامنه-اصلی-شما
```

- در Vercel: **Settings → Environment Variables** این مقدار را ست کنید و دوباره
  Deploy بگیرید.
- اگر دامنهٔ اختصاصی دارید (مثلاً `vatandar.ir`)، در تنظیمات دامنهٔ Vercel،
  دامنهٔ `vatandar-menu.vercel.app` را با **Redirect** به دامنهٔ اصلی بفرستید
  تا محتوا دو جا ایندکس نشود (Duplicate Content).
- اگر متغیر را ست نکنید، همه‌چیز روی آدرس پیش‌فرض ورسل کار می‌کند.

> نکته: متغیرهای `NEXT_PUBLIC_*` در زمان build جایگزین می‌شوند؛ بعد از تغییر
> حتماً Redeploy کنید.

## ۳) گوگل سرچ کنسول (۱۰ دقیقه، بیشترین اثر)

1. وارد <https://search.google.com/search-console> شوید.
2. نوع property را **Domain** یا **URL prefix** دامنهٔ اصلی انتخاب کنید.
   - تأییدیهٔ متا (`google-site-verification`) از قبل در `app/layout.tsx` هست؛
     فایل `public/googleec72074d61f7d798.html` هم هنوز سر جایش است، پس تأیید
     خودکار انجام می‌شود.
3. از منوی **Sitemaps** آدرس `https://دامنه/sitemap.xml` را Submit کنید.
4. برای سرعت ایندکس اولیه، آدرس‌های `/`، `/branches`، `/menu`، `/about` را
   با **URL Inspection → Request Indexing** ثبت کنید.
5. یک هفته بعد، بخش **Performance** را ببینید: کوئری‌هایی مثل «وطندار»،
   «رستوران وطندار مشهد» باید impression بگیرند.

## ۴) پروفایل کسب‌وکار گوگل (برای جست‌وجوی محلی حیاتی است)

برای اینکه در سرچ «وطندار» و «رستوران افغانی مشهد» در **نقشه و نتایج محلی**
بالا بیایید:

1. در <https://business.google.com> پروفایل «رستوران وطندار» بسازید.
2. دسته‌بندی: `Afghan restaurant` / `Restaurant`.
3. آدرس دقیق، تلفن، ساعت کاری و **لینک وب‌سایت = دامنهٔ اصلی** را وارد کنید.
4. عکس فضای رستوران (همان عکس‌های `public/branch*`) اضافه کنید.
5. از مشتری‌ها بخواهید روی پروفایل گوگل نظر بگذارند؛ این با
   `aggregateRating` سایت هم‌افزایی می‌کند.

## ۵) از کجا چه چیزی را عوض کنم؟

همه‌چیز در **`lib/seo.ts`** متمرکز است:

- `SITE_URL` ← از env خوانده می‌شود (دستی تغییر ندهید).
- `SEO_DEFAULTS` ← شهر، استان، ساعت کاری (`opens`/`closes`)، نوع غذاها،
  محدودهٔ قیمت و ضریب تبدیل تومان→ریال.
- `DEFAULT_DESCRIPTION` و `KEYWORDS` ← متن توضیح و کلیدواژه‌ها.
- `BRAND` ← نام برند به سه زبان.

اطلاعات شعبه‌ها (نام، آدرس، تلفن، مختصات) و منو و امتیازها **از دیتابیس**
خوانده می‌شوند؛ یعنی هر تغییری در پنل مدیریت، حداکثر تا **یک ساعت** بعد در
Structured Data و sitemap منعکس می‌شود (کش `unstable_cache`).

## ۷) رفتار صفحهٔ اصلی (تصمیم شما حفظ شد)

مسیر `/` همچنان کاربرِ بدون شعبهٔ انتخاب‌شده را به `/branches` می‌فرستد.
به همین دلیل `/branches` عملاً صفحهٔ فرود خزنده‌هاست و متادیتای برند-محور
گرفته است. اگر روزی خواستید صفحهٔ اصلی محتوای مستقل داشته باشد، کافیست
ریدایرکت در `components/hooks/useBranchData.ts` را بردارید؛ زیرساخت متادیتا
و Structured Data از قبل آماده است.
